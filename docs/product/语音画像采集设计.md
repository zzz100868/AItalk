## 目标与边界

语音通话的首要目标是在约 15 分钟内，为匹配系统采集 10 个人格维度的有效证据。用户感知应当是一次节奏清楚、容易回答的语音访谈，而不是自由陪聊，也不是逐题完成 66 题问卷。

- 10 个维度是 coverage checklist 的基本单位。
- 66 题是题源、证据来源和映射依据，不是单次通话的完成清单。
- 首次通话尽量触达全部 10 个维度；时间不足时优先高权重维度，缺口留到下次续采。
- D10 社会态度需要主动采样，放在通话中后段，以“关注议题偏好”等低压力措辞提问。
- 不承诺一通电话得到稳定结论；画像由多次通话持续补证和校正。

## 交互原则

### 问题形态

- 每个 AI 回合只提出一个主问题，最多一个问号。
- 主问题优先给 3-4 个选项，用户可只选，也可继续解释。
- 允许一个问题同时采样 2-3 个关联维度，但不并列多个独立问题。
- 尽量减少开放题。只有选项无法表达、用户主动展开或需要澄清时才使用开放追问。
- 回答过短时只追问一次；仍无补充则保留弱证据并推进 checklist。
- 用户可以说“跳过”“不想聊”；同一通电话内不强行重问，下次只做低压力复核。

### 对话节奏

- 语气为 70% 访谈主持人、30% 朋友：清楚、放松、克制。
- 减少寒暄和闲聊，每个正常回合都应推动采集、澄清或确认。
- 可以做简短评价，但不能让评价取代提问。
- 禁止高频口头禅和闺蜜化称呼，例如“懂”“嗯嗯”“宝”“亲”“姐妹”“我懂你”。
- 每轮使用“轻确认 + 下一个问题”；每 3-4 轮可做一句阶段小结。
- 开场可透明说明“接下来会问一些容易回答的选择题”，但不说“画像采集”“人格采样”或“66 题”。

## 15 分钟路线

| 时间 | 目标 | 主要维度 |
|---|---|---|
| 0:00-0:45 | 透明开场，说明选择题式交流 | — |
| 0:45-3:00 | 低压力热身，提高回答速度 | D4、D5、D8 |
| 3:00-5:30 | 表达与沟通习惯 | D6、D7 |
| 5:30-8:00 | 关系期待与家庭模式 | D1、D2 |
| 8:00-10:00 | 核心价值观及关系取舍 | D3，补 D1/D7 |
| 10:00-12:00 | 关注议题与社会态度 | D10，补 D3/D8 |
| 12:00-13:45 | 未来计划和 checklist 补缺 | D9、缺失维度 |
| 13:45-15:00 | 3-5 条暂定总结，接受用户修正 | 全局确认 |

这是一条优先级路线，不是硬编码顺序。用户情绪、跳过项、已有画像和上次未完成项会改变本轮候选卡片。

## Probe Card 题库

### MVP 规模

首版维护 25-35 张高质量 `probe_card`。高权重维度 D1、D2、D3、D6、D7 各 4-5 张，其余维度各 2-3 张；复合卡片可覆盖 2-3 个维度。

LLM 不自由发明问题。规则引擎先根据阶段和 checklist 生成少量候选卡片，LLM 只负责：

1. 从候选中选择当前最合适的卡片；
2. 在不改变选项与含义的前提下做轻量口语化；
3. 根据用户回答补充证据文本和理由强度。

LLM 失败时直接使用卡片标准话术，不中断采集。

### 卡片结构

```ts
interface ProbeCard {
  id: string;
  version: number;
  optionMappingVersion: number;
  stage: string;
  prompt: string;
  options: Array<{
    id: string;
    label: string;
    signals: Array<{
      dimension: DimensionId;
      label: string;
    }>;
  }>;
  sourceQuestionIds: string[];
  targetDimensions: DimensionId[];
  followUpPrompt?: string;
}
```

证据必须保存 `cardId`、`cardVersion`、`optionMappingVersion`、`optionId`、`sourceQuestionIds` 和 `targetDimensions`，以便题库升级后仍可追溯历史解释。

## Coverage Checklist

每个用户维护一份跨通话的 checklist，而不是每通电话从零开始。每个维度至少记录：

```ts
interface DimensionCoverage {
  confidence: number;
  evidenceCount: number;
  status: 'missing' | 'weak' | 'covered' | 'skipped' | 'needs_recheck';
  lastProbedAt?: string;
  lastCardId?: string;
  skippedInSessionId?: string;
}
```

候选优先级综合考虑：阶段适配、高低权重、置信度缺口、距离上次提问时间、是否在本通跳过、卡片是否已使用以及用户当前情绪。信息不足时不强行凑满 10 维，按以下顺序处理：

1. 优先 D1、D2、D3、D6、D7；
2. 再补 D4、D5、D8、D9；
3. D10 在中后段主动采样，作为较低权重副信号；
4. 剩余缺口保存到下次通话。

## 证据与置信度

| 回答质量 | 建议置信度增量 |
|---|---:|
| 只选择一个选项 | 0.10-0.15 |
| 选择选项并给出简短理由 | 0.18-0.22 |
| 给出具体经历或稳定例子 | 0.25-0.30 |
| 用户主动纠正系统理解 | 0.30 |
| ASR 低置信度或文本不完整 | 最大 0.10 |

固定选项映射提供弱证据，LLM 只判断理由强度和提取原话，不得改变卡片的维度映射。画像置信度上限为 1.0。

用户纠正时不删除旧证据：新建高优先级纠正证据，把旧证据标为 `superseded`，必要时将维度标为 `needs_recheck`。纠正回合不推进 checklist。

## 中断、挂断与续采

- AI 说话时用户插话：立即停止当前 TTS，进入 ASR；被打断的 AI 问题不自动算作已回答。
- 用户说到一半挂断：保存已完成证据、当前卡片和 coverage 快照，结束原会话。
- 下次打开小程序：创建新语音会话，不续播原始上下文；开场自然承接，并优先补上次缺口。
- 结束原因统一为 `completed`、`user_ended`、`abandoned`、`timeout_ended`。
- 用户使用“不是”“我刚才说的是”“你听错了”等纠正语句时进入纠正模式，不推进 checklist。

## 收尾确认

最后约 1 分钟，AI 用 3-5 条暂定描述总结本次理解，并明确允许用户修正。总结应使用“目前听起来”“我先暂时记成”等非定论措辞。

用户确认后记录 `completed`；用户修正时按强证据写入，再做简短确认。若超时或提前挂断，coverage 仍然保存，但本次会话不标记为完整完成。

## 降级策略

| 故障 | 降级行为 |
|---|---|
| LLM 选卡/生成失败 | 规则引擎选卡，直接使用卡片标准话术 |
| LLM 证据抽取失败 | 使用固定选项映射写入弱证据 |
| TTS 失败 | 至少向客户端返回文字并结束当前 AI 回合 |
| ASR 失败或文本为空 | 请用户重复，不推进 checklist |
| WebSocket 断开 | 保存 coverage 和结束原因 `abandoned` |
| Mock 模式 | 按 probe_card 顺序循环，不再随机返回陪聊陈述 |

## 已知取舍

优点是采集目标明确、15 分钟信息密度高、问题质量可审查、证据可追溯，且断线后可以续采。主要代价是对话自由度下降、题库需要持续维护、复合问题可能产生映射偏差，以及规则引擎与 LLM 选择不一致时需要额外监控。

MVP 接受这些代价，但必须保留跳过、纠正、降级和跨通话续采，避免把用户锁进机械问卷。

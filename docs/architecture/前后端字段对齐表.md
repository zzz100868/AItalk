# 前后端字段对齐表

**状态**：当前契约校准（2026-07-12）
**原则**：API 成功时以后端响应为准；mock 和 storage 只用于明确的开发回落。
**接口细节**：[API 总览](../api/README.md)

## 1. 通用命名

| 语义 | 后端/API | 前端页面/Store | 处理 |
|---|---|---|---|
| 用户 ID | `id`、`userId` | `id`、当前部分位置用 `author` | 新契约统一为 `userId` |
| 昵称 | `nickname` | `nickName` / `name` | API 层或页面显式映射 |
| 头像 | `avatar` | `avatar` / `userAvatar` / `matchAvatar` | 页面展示字段 |
| 简介 | `bio` | `bio` / `matchBio` | 页面展示字段 |
| 时间 | ISO8601 或模块格式化字符串 | `time` / `date` | 不在前端猜测数据库时区 |

## 2. Auth

`POST /api/auth/wx-login`：

| 后端 | 前端去向 |
|---|---|
| `token` | `aitalk_token` storage |
| `user.id` | `userStore.id` |
| `user.nickname` | `userStore.nickName` |
| `user.avatar` | `userStore.avatar` |
| `user.bio` | `userStore.bio` |

`openid` 和 `realNameVerified` 当前不驱动页面核心状态。后端身份仍是 mock。

## 3. Profile

`GET/PUT /api/me` 与前端映射：

| API | 页面/Store |
|---|---|
| `id` | `userInfo.id` / `userStore.id` |
| `nickname` | `userInfo.nickName` / `userStore.nickName` |
| `avatar` | `userInfo.avatar` / `userStore.avatar` |
| `bio` | `userInfo.bio` / `userStore.bio` |
| `realNameVerified` | 尚未稳定接入页面 |

照片 API 返回 `{photos: [{id, url, sortOrder}]}`，但 profile 页当前使用本地路径 `photos: string[]`。接入时必须保留后端 photo id，不能只保存 URL，否则无法可靠删除。

`GET /api/users/:author/home` 当前响应 `name`、`handle`、`avatar`、`bio`、`isMe`。`author` 实际按 user id 查询；前端仍可能传昵称，这是待确认契约。

## 4. Memory

### Chat

| API | 前端 |
|---|---|
| `data[].id` | message `id` |
| `data[].sender` | `user` / `ai` |
| `data[].content` | message `content` |
| `meta.chatDays` | `chatDays` |
| `meta.chatMood` | `chatMood` |
| `meta.chatTopics` | `chatTopics` |
| `reply.content` | 前端逐字渲染内容 |

### Insights

API 和前端都使用：`id`、`date`、`title`、`content`、`tag`、`tagColor`、`category`。mock id 可能是 number，数据库 id 是 string；页面事件参数应保持原值，不做数值转换。

当前前端读取 API，但编辑/删除尚未调用 API。

### Archive

双方字段一致：`aboutMe`、`personalities[{name, desc}]`、`traits[{name, color}]`。

## 5. Match

| API | 前端 data |
|---|---|
| `isOpen` | `isMatchOpen` |
| `hasResult` | `isMatched` |
| `match.id` | `matchId` |
| `match.avatar` | `matchAvatar` |
| `match.name` | `matchName` |
| `match.bio` | `matchBio` |
| `match.compatibility` | `compatibility` |
| `match.tags` | `tags` |
| `match.icebreakers` | `icebreakers` |
| `match.insight` | `matchInsight` |
| `match.unlocked` | `unlocked` |

`nextOpenAt` 当前由前端重新计算倒计时，没有直接用后端时间；应由前端负责人确认是否改为服务端时间权威。

## 6. Notifications

字段直接对应：`id`、`type`、`author`、`avatar`、`content`、`time`、`read`。列表外层还返回 `hasMore`、`cursor`、`unreadCount`。

后端真实类型当前主要是 `match`；前端 fallback 仍包含 `follow`。筛选和点击行为需要兼容未知类型，不能假设只有 follow。

## 7. Payment

`POST /api/pay/create-order`：

| API | 前端行为 |
|---|---|
| `success` | 决定是否继续 |
| `orderId` | 当前未持久化到页面状态 |
| `wxPayParams` | 传给 `wx.requestPayment` |
| `error` / `message` | toast |

`wxPayParams: null` 表示开发 mock，不代表权益已解锁。

## 8. Voice WebSocket

协议字段以 `server/voice-gateway/types.ts` 和 [Voice API](../api/voice.md) 为准。前端只消费事件，不推断后端内部状态。

关键映射：

| 事件 | 前端状态 |
|---|---|
| `asr_partial` / `asr_final` | `asrText` |
| `asr_ready` | 允许录音 frame 上行 |
| `ai_reply_audio.text` | `aiText` |
| `ai_reply_audio.pcmBase64` | TTS 播放队列 |
| `ai_turn_end` | 回合播放结束/被打断 |
| `session_end` | 结束通话并跳转 archive |
